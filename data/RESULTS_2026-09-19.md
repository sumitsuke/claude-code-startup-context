## Corrections (after review)

1. **Additivity.** Expected D from A1 = 74,233 − 11,722 − 8,439 = 54,072; measured 53,925; residual **−147** — not "within a few tens" as the original file claimed. But the baseline itself moved during the series: A4 (right after D) = 74,079 = A1 **−154**, and the two transcripts differ in exactly one attachment, `session_context` (git status text 3,466 → 3,280 chars; all other 11 attachments byte-identical). Against the local baseline A4: expected 74,079 − 11,722 − 8,439 = 53,918, measured 53,925, residual **+7**. Conclusion unchanged (the two effects add), the basis is now the right one. `scripts/measure.py` reports both residuals.
2. **P is a discarded run, not a "snapshot off" effect.** The original sentence attributed P − A1 = −6,860 to `--system-prompt-snapshot on` vs. off. That is wrong: `on` is the CLI default (`claude --help`), so P, A2, A3 and A4 all ran with the snapshot on and only A1 had the flag written out. P has `cache_read 0` (every other run: 36,498) and a 14,573-char `skill_listing` attachment (every other run: 9,252) — a different prefix, exactly the kind of run this README says to discard. The 6,860 is not attributed to anything. The −1,140 of the pre-run (04:59 JST, 73,093, MCP tool names 221 of 266, `cache_read 0`) is likewise a different prefix and stays unexplained.
3. **MEMORY.md size limit.** The raw file was 29,009 bytes, above the documented "first 200 lines or 25KB", yet the `instructions` attachment contained it to the last line (lines 3, 118, 119 and the last one checked). How the limit is evaluated internally (e.g. after preprocessing) was not investigated; the original file's guess "counted in characters" is withdrawn as unverified.
4. File names in the original tables refer to the internal scripts (`_実験_基礎の分解_2026-09-19.py`, `_実験_D_2026-09-19.py`); in this repository they are `original_2026-09-19/experiment_startup_decomposition_2026-09-19.py` and `…/experiment_D_additivity_2026-09-19.py`.
